# Smart-Platform-for-Reliable-Building-Material-Delivery-Verification# 多模态智能验收与风险审查助手--建筑材料全链追溯系统


## 项目作品简介

本作品面向建筑材料交付与进场验收场景，以单批次建筑材料为核心对象，构建“出厂建档—运输监控—到场核验—风险提示”的连续交付链路。

系统利用多模态大模型识别出厂质量证明书、材料铭牌和到场标签中的厂家、规格、牌号、批次号等信息，将非结构化图片或 PDF 转换为统一的结构化材料档案；在运输阶段，结合地图轨迹、路线偏离、异常停留和定位中断等信息进行过程风险监测；材料到场后，再次识别现场铭牌并与出厂档案进行首尾核验，最终生成包含事实依据、风险解释和核查建议的辅助验收结论。

作品重点解决以下问题：

- 材料出厂资料依赖人工录入，效率低且容易错录；
- 材料运输过程只有位置记录，缺少异常事件的直观表达；
- 出厂材料与到场材料之间缺少自动化身份一致性核验；
- 质量资料、运输轨迹和到场信息彼此割裂，监理难以快速形成综合判断；
- 现有追溯系统通常只能“展示记录”，不能主动发现冲突并解释风险。

本作品不以大模型替代监理人员作出最终验收决定，而是通过“多模态识别 + 确定性规则 + 轨迹分析 + 大模型解释”辅助专业人员提高核验效率和风险发现能力。

# 1. 背景与场景

## 1.1 目标用户

### 1.1.1 主要用户

#### 施工现场监理工程师

- **用户身份**：负责建筑材料进场验收、质量资料审查和异常处置。
- **年龄或职业阶段**：通常为具有一定工程经验的在岗专业人员，可能处于项目一线或项目管理阶段。
- **行为特征**：
  - 需要频繁核对采购订单、出厂资料、检测报告和现场材料信息；
  - 对材料批次、规格、供应商和质量文件的一致性较为敏感；
  - 工作节奏快，通常需要在较短时间内完成材料验收判断。
- **数字化能力**：
  - 能够使用办公软件、项目管理平台、手机拍照和扫码工具；
  - 不一定熟悉大模型、GIS 算法或复杂的数据分析工具；
  - 更偏好直接、可视化、可追溯的结果展示。

#### 项目材料员或质量员

- **用户身份**：负责材料接收、资料归档、现场登记和问题反馈。
- **行为特征**：
  - 经常需要录入厂家、规格、批次号、数量和出厂日期等信息；
  - 需要在多个文件、表格和系统之间重复搬运数据；
  - 容易因扫描件模糊、材料批次多或字段名称不统一产生录入错误。
- **数字化能力**：
  - 熟悉手机、小程序和常见项目管理系统；
  - 对操作流程的简洁性和自动填充能力要求较高。

### 1.1.2 次要用户

- 项目经理及项目质量负责人；
- 建设单位或总承包单位管理人员；
- 采购与供应链管理人员；
- 材料供应商及物流管理人员。

这些用户更关注材料交付进度、风险事件、验收状态和责任证据，而不一定直接操作资料识别与现场核验功能。

## 1.2 用户痛点与问题定义

### 1.2.1 痛点一：出厂资料录入依赖人工

#### 具体场景

材料出厂时，供应商通常提供质量证明书、合格证、铭牌照片等资料。材料员或监理需要手工读取并录入：

- 生产厂家；
- 材料名称；
- 牌号或等级；
- 规格型号；
- 批次号；
- 炉号；
- 出厂日期；
- 执行标准。

#### 现有解决方式

- 人工查看扫描件或照片；
- 手工填写 Excel、项目管理系统或纸质台账；
- 人工将出厂资料与采购信息关联。

#### 现有方式不足

- 同一字段在不同厂家文件中的名称不统一；
- 复杂表格、合并单元格和扫描件增加录入难度；
- 批次号、规格和日期等字段容易错录；
- 同一份资料需要在不同系统中重复录入；
- 出错后不易及时发现。

#### 核心问题

如何将不同版式的材料质量文件快速、准确地转换为统一结构化数据，并减少人工重复录入。

---

### 1.2.2 痛点二：运输过程可见，但异常不够直观

#### 具体场景

车辆从材料厂出发后，管理人员通常只能查看当前位置、历史轨迹和到达状态，难以快速识别：

- 是否偏离规划路线；
- 是否在非授权区域长时间停留；
- 是否出现定位中断；
- 是否发生明显运输超时；
- 异常事件发生在什么时间和地点。

#### 现有解决方式

- GPS 或北斗定位；
- 地图轨迹回放；
- 人工查看车辆路线；
- 基于固定阈值的简单告警。

#### 现有方式不足

- 原始轨迹点数量多，人工查看成本高；
- 异常事件与材料批次信息未必直接关联；
- 告警往往只显示“异常”，缺少事件背景和核查建议；
- 运输异常与到场核验结果彼此割裂。

#### 核心问题

如何将运输轨迹自动转化为可理解的异常事件，并与具体材料批次绑定展示。

---

### 1.2.3 痛点三：出厂材料与到场材料缺少首尾一致性核验

#### 具体场景

材料到达项目现场后，监理需要核对到场铭牌、出厂质量证明书和采购订单中的厂家、规格、牌号和批次号是否一致。

#### 现有解决方式

- 人工拍照；
- 人工逐项比对；
- 发现问题后通过电话、微信或纸质记录反馈。

#### 现有方式不足

- 批次号较长，容易漏看或看错；
- 到场标签与出厂文件的字段格式可能不同；
- 人工核验结果缺少统一结构化记录；
- 单独发现一个字段不一致时，难以快速结合运输过程判断风险程度。

#### 核心问题

如何通过到场图像识别完成出厂信息与到场信息的自动对照，及时发现批次、规格或牌号冲突。

---

### 1.2.4 痛点四：跨阶段信息割裂，难以形成综合判断

#### 具体场景

监理需要同时考虑：

- 采购订单要求；
- 出厂质量资料；
- 材料身份信息；
- 运输轨迹；
- 到场铭牌；
- 异常事件。

但这些信息往往分散在不同人员、文件和系统中。

#### 现有解决方式

- 人工汇总；
- 多系统切换；
- 依赖个人经验判断；
- 通过微信群、电话或纸质单据协调。

#### 现有方式不足

- 信息检索和汇总耗时；
- 判断标准依赖个人经验；
- 异常事实、风险推断和处理建议没有清晰区分；
- 过程难以完整回放。

#### 核心问题

如何围绕同一材料批次，将出厂、运输和到场三个阶段的信息串联起来，并生成有证据依据的辅助验收建议。

---

### 1.2.5 数据佐证说明

当前方案尚未获得真实项目中的材料验收时长、错录率、异常运输发生率等统计数据，因此暂不设置未经验证的量化指标。

后续可通过以下方式补充数据依据：

- 访谈监理工程师、材料员和项目质量负责人；
- 统计单批次材料资料录入与核验平均耗时；
- 统计人工录入字段错误率；
- 统计运输异常人工发现与系统发现的差异；
- 统计到场批次信息不一致的实际发生情况；
- 记录 AI 识别结果的人工修正次数。

## 1.3 使用场景

### 场景一：正常材料交付

1. 供应商提交出厂质量证明书和材料铭牌照片；
2. 系统利用多模态大模型提取厂家、牌号、规格、批次号和出厂日期；
3. 用户确认识别结果后，系统生成材料数字档案；
4. 材料与运输任务绑定，地图显示规划路线和实际轨迹；
5. 车辆正常到达项目现场；
6. 监理上传到场铭牌照片；
7. 系统识别到场信息，并与出厂档案进行首尾核验；
8. 所有关键字段一致，系统生成“未发现明显身份冲突”的辅助结论。

### 场景二：异常材料交付

1. 系统完成出厂资料识别和材料建档；
2. 运输途中，车辆偏离规划路线并在非授权区域停留；
3. 停留期间出现一段定位数据中断；
4. 材料到场后，系统识别到场铭牌；
5. 到场批次号与出厂档案中的批次号不一致；
6. 系统将运输异常和身份冲突进行汇总；
7. 大模型生成结构化风险说明：
   - 已确认事实；
   - 风险解释；
   - 建议核查材料；
   - 辅助验收建议；
8. 监理选择“暂缓验收”“补充资料”或“人工复核”。

## 1.4 价值体现

### 1.4.1 提升资料录入效率

通过多模态模型自动读取质量证明书和铭牌信息，减少材料员重复录入厂家、规格、批次号等字段的工作量。

### 1.4.2 降低人工核验错误

系统将出厂信息和到场信息并列展示，对不一致字段进行高亮，降低因长批次号、字段格式差异和人工疏忽造成的漏检风险。

### 1.4.3 提升运输过程透明度

通过地图轨迹、车辆动画、异常点和事件时间轴，将材料运输过程从静态记录转化为动态、可理解的交付过程。

### 1.4.4 提高风险发现能力

系统不仅记录车辆轨迹，还能够根据路线偏离、异常停留、定位中断和运输超时等规则提取风险事件。

### 1.4.5 支持跨阶段综合判断

将出厂资料、运输轨迹和到场信息统一绑定到同一材料批次，避免各阶段信息彼此孤立。

### 1.4.6 改善监理决策体验

大模型将结构化异常转化为“事实—风险—建议”的清晰说明，帮助监理快速理解问题，而不是直接面对大量原始数据。

### 1.4.7 强化过程留痕

材料从出厂到到场的每个关键阶段均保留时间、资料、轨迹和核验结果，为后续复核、责任追溯和质量管理提供依据。

# 2. 功能说明

## 2.1 核心功能

### 2.1.1 出厂资料多模态识别

| 项目     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 功能名称 | 出厂资料智能识别                                             |
| 用户输入 | 出厂质量证明书、合格证、材料铭牌照片或 PDF                   |

| 项目     | 说明                                                        |
| -------- | ----------------------------------------------------------- |

| 用户输入 | 经用户确认的结构化出厂信息                                  |

```text
✓ 出厂建档  →  ⚠ 运输中  →  ○ 到场核验
```

### 2.1.4 运输轨迹可视化

| 项目     | 说明                                               |
| -------- | -------------------------------------------------- |
| 功能名称 | 材料运输地图监控                                   |
| 用户输入 | 规划路线、模拟或真实 GPS 轨迹点                    |
| 处理方式 | 地图组件绘制规划路线、实际路线、车辆位置和运输进度 |
| 输出结果 | 车辆动画、路线回放、当前距离、预计到场时间         |
| 解决问题 | 提高运输过程的直观性和可展示性                     |

### 2.1.5 运输异常检测

| 项目     | 说明                                               |
| -------- | -------------------------------------------------- |
| 功能名称 | 运输风险事件识别                                   |
| 用户输入 | 带时间戳、经纬度和速度的轨迹数据                   |
| 处理方式 | 规则算法检测路线偏离、异常停留、定位中断和运输超时 |
| 输出结果 | 异常类型、发生时间、持续时长、位置和风险等级       |
| 解决问题 | 从大量轨迹点中筛选需要人工关注的异常事件           |


- 实际轨迹偏离规划路线超过设定阈值；
- 非授权区域停留超过设定时长；
- 相邻定位点时间间隔超过设定阈值；
- 实际到场时间超过预计到场时间。

### 2.1.8 综合风险分析与辅助验收建议

| 输出结果 | 综合风险等级、已确认事实、风险解释、核查建议和辅助验收建议 |

```json
{

    "调取异常停留期间的装卸记录",

```

### 2.2.4 多模态识别方案

#### 输入

- 所有模型结果保留原始文件和证据来源。

### 2.2.6 运输轨迹与异常检测方案

#### 轨迹数据结构

```json
{
  "longitude": 108.9001,
  "latitude": 34.2501,
  "speed": 42.5,
  "timestamp": "2026-07-23T14:12:00"
}
```

#### 异常检测规则

1. **路线偏离**  
   计算实际轨迹点到规划路线的最短距离，超过阈值后生成偏航事件。

2. **异常停留**  
   连续多个点速度接近零，持续时间超过阈值，且位置不属于授权停留区域。

3. **GPS 定位中断**  
   相邻轨迹点时间间隔超过阈值。

4. **运输超时**  
   实际到场时间超过预计到场时间。

### 2.2.7 大模型风险解释方案

大模型不直接处理原始 GPS 坐标，也不直接决定材料是否合格。

输入给大模型的是已经由程序确认的结构化结果：

```json
{
  "identityCheck": {
    "batchMatch": false,
    "gradeMatch": true,
    "specificationMatch": true
  },
  "transportAnomalies": {
    "routeDeviationKm": 5.2,
    "unauthorizedStopMinutes": 45,
    "gpsGapMinutes": 15
  }
}
```

大模型负责：

- 汇总已确认事实；
- 区分事实与风险推断；
- 生成可理解的风险说明；
- 给出核查建议；
- 输出辅助验收建议。

提示词约束：

- 不得断言材料已经被调换；
- 不得编造输入中不存在的时间、地点或证据；
- 必须区分“已确认事实”“风险解释”“核查建议”；
- 最终决定由监理人员确认。

### 2.2.9 AI、规则与人工的责任边界

| 能力                     | 负责技术         |
| ------------------------ | ---------------- |
| 材料文件内容识别         | 多模态大模型     |
| 结构化字段确认           | 用户人工确认     |
| 材料批次建档             | 传统后端系统     |
| GPS 轨迹展示             | 地图组件         |
| 路线偏离、停留、中断判断 | 确定性规则       |
| 出厂与到场字段比对       | 程序规则         |
| 风险说明与核查建议       | 大语言模型       |
| 最终验收决定             | 监理或质量负责人 |

核心原则：

> 传感器和业务系统记录事实，规则程序完成确定性判断，大模型负责理解和解释，专业人员承担最终决策责任。
